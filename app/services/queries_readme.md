# 📊 Query Engine — `app/services/queries.py`

This module powers all **analytical and reporting queries** in CLEAR. It reads normalized parquet data (produced by `normalize_parquet.py`) and exposes a set of composable, high-level queries used by the web UI and API.

---

## 🧩 Purpose

`queries.py` provides a consistent interface between the parquet-backed financial dataset and the Flask UI.  
It uses **DuckDB** to query and aggregate large amounts of transaction data efficiently, with minimal in-memory overhead.

The key idea: importers and normalizers focus on _data ingestion_; `queries.py` focuses on _data insight_.

---

## ⚙️ Core Responsibilities

1. **Aggregate spending, income, and refunds** by various dimensions (category, institution, tag, month, cardholder, etc.).
2. **Compute net worth** across assets and liabilities over time.
3. **Merge manual, NAV, and transactional balances** for unified reporting.
4. **Provide a consistent query API** for `/accounts`, `/transactions`, and dashboard components.

---

## 🧱 Architecture Overview

### Input
All parquet data generated by `normalize_parquet.py` and stored under the consolidated root directory, e.g.:
```
/media/user/clear/consolidated_statements/
├── year=2025/month=08/transactions.parquet
└── _meta/
    ├── accounts.parquet
    ├── account_balances.parquet
    ├── manual_values.parquet
    ├── nav_snapshots.parquet
    └── statement_sources.parquet
```

### Query Flow
```
Parquet files → DuckDB Views → Query Functions → DataFrames → Flask UI
```

1. **Collects all parquet files** recursively.
2. **Builds a DuckDB view** using `read_parquet([...], union_by_name=true)`.
3. **Executes parameterized SQL** for each query type.
4. **Returns a Pandas DataFrame** back to Flask for visualization.

---

## 🧰 Key Components

### 1. Normalization and File Scanning

- `collect_parquet_files(path)` → Recursively finds parquet files under the root directory.
- `build_scan_sql(files)` → Builds a SQL statement for DuckDB that unions all input parquet files.
- `_meta_path()` → Shortcut for meta files (`_meta/accounts.parquet`, etc.).

### 2. Query Dispatcher

`run_query(name: str, parquet_path: str, **kwargs)` is the **public API** used by Flask routes.
It dynamically dispatches to one of the functions listed in `QUERY_MAP`.

Examples:
```python
run_query("total_spending_by_category", parquet_path)
run_query("net_worth_accounts_snapshot", parquet_path)
```

The dispatcher:
- Loads the relevant parquet files.
- Creates a DuckDB connection.
- Executes the requested query function.
- Returns a Pandas DataFrame to the caller.

## 💸 Spending & Income Queries

The spending queries use SQL over a `base` CTE that ensures consistent normalization of dates (`op_date`) and description text (`description_norm`).

### Category-Level Queries
- `total_spending_by_category()` → Aggregate spending per category.
- `total_spending_by_category_subcategory()` → Adds subcategory grouping.
- `total_spending_by_category_subcategory_type()` → Full hierarchy: category / subcategory / type.

### Tag-Level Queries
Tags are derived from `tags.json` through the category-to-tag map built in `app/services/categories.py`.
- `total_spending_by_tag()` → Total spending by tag.
- `total_spending_by_tag_month()` → Monthly evolution of spending by tag.

### Entity-Level Queries
- `total_spending_by_cardholder()` → Total outflow per cardholder.
- `total_spending_by_institution()` → Total outflow per merchant or financial institution.
- `total_spending_by_month()` → Net spending per month (refunds reduce totals).

---

## 💰 Transaction & Transfer Queries

- `transactions_by_cardholder()` → Raw transactions grouped by cardholder.
- `transactions_by_institution()` → Raw transactions grouped by merchant/institution.
- `all_transactions()` → Combines all transactional data with manual values and account metadata.
- `all_transfers()` → Lists transactions of type `transfer`.

`all_transactions()` merges three sources:
1. Transactional data from year/month parquet files.
2. Manual values from `_meta/manual_values.parquet`.
3. Account names from `_meta/accounts.parquet`.

---

## 🧮 Net Worth & Balance Queries

### `net_worth_timeseries()`
Computes monthly net worth using data from:
- Transactions (aggregated deltas per account per month)
- Manual values (interpolated with forward-fill)
- NAV snapshots (investment accounts)

Output columns:
| month | assets | liabilities | net_worth |

Balances are grouped by `account_side` (asset vs liability) and netted monthly.

### `net_worth_accounts_snapshot()`
Combines **statement**, **manual**, **NAV**, and **transaction-derived** balances, in that order of priority.
Used by the `/accounts` page to display latest per-account values.

Priority order:
1️⃣ Statement summary (`_meta/account_balances.parquet`)
2️⃣ Manual values (`_meta/manual_values.parquet`)
3️⃣ NAV snapshots (`_meta/nav_snapshots.parquet`)
4️⃣ Derived transactions
